S³-S2ST：让流式同传自己学「什么时候可以下笔」——用语义对齐的增量监督，阈值一调就换质量/延迟曲线，代码与 4B 权重已开源 ⭐

📅 2026-11-25👥 Yuxiang Zhao、Zhiyun Fan、Yu Pu、Yanjie An、Yushen Chen、Wenrui Liang、Baiji Liu、Yunchong Xiao、Zhaoci Liu、Keqi Deng、Kai Yu、Zhifu Gao、Xiangang Li、Xie Chen
流式语音到语音翻译（S2ST）最难的不是「翻得准」，而是「什么时候翻」——输入还在一句句往里流，模型必须自己判断当前这段部分输入是否已经足以稳定产出译文并把语音说出来，判断早了译文要返工，判断晚了延迟崩掉。这篇（v3 版本，本期更新并放出代码与 4B 权重）的做法是把「提交时机」也变成可学习对象：将语句级语音对转换成增量训练样本，从语义对齐的角度监督「此刻是否已经产生一个完整的、值得提交的语义单元」，训练出一个提交策略（policy），而策略的输出阈值在推理时可调，从而在固定的 640 ms 输入网格上直接控制质量—延迟的权衡曲线。结果上：英中方向在 FLEURS 上有竞争力，在自建的 9 语对测试集上翻译质量领先所对比的流式系统；在 RealSI 上，把阈值与已缓冲语音长度联动（缓冲多了就放宽阈值）可以进一步提质量，而首次出声延迟（first-audio latency）几乎不变。对做同传产品的团队，这篇最实用的是它把「延迟」从一个工程旋钮变成了模型内生的决策变量，且训练/推理代码与权重已开源于 github.com/QwenAudio/S3-S2ST。原始 v1 提交于 10-27，本期为 v3。

MOZAIC：不只问「这段是真是假」，而是四选一告诉你伪在画面还是伪在声音——13.7 万条配对样本，12 个音视频 MLLM 最高只有 35.6% ⭐

📅 2026-11-25👥 Shaina Raza、Mohamed Hafez、Ahmed Y. Radwan、Khalid Elgazzar、Kathryn Hume
音视频深伪可以伪造人脸、伪造声音，或者两者都伪造。现有基准大多只问「真还是假」，于是无法回答一个对检测与取证都更关键的问题：这个检测器到底在看画面、在听声音，还是在看编码痕迹？MOZAIC 的构造思路很直接也很费力——每一段源视频都同时放出四种组合（真画面+真声音 / 真画面+假声音 / 假画面+真声音 / 假画面+假声音），共 137,745 条片段、15,014 组源配对，伪造类型覆盖内脸替换、整帧视频扩散生成与声音转换（voice conversion）。任务分四个：T1 音视频真实性四分类、T2 篡改类型、T3 身份核验、T4 解释。评测结果显示出一个很扎眼的偏差：最好的音视频 MLLM 在四分类 T1 上只有 35.6%，且对「只伪造画面」的识别率（43.6%）远高于「只伪造声音」（7.5%）——换句话说，当前多模态大模型严重依赖视觉通道，几乎是「听觉盲」。专门训练的检测器 T1 能到 98.4%，但把换脸生成器留出训练集后掉到 78.3%，泛化仍是开放问题；LoRA 微调能明显提升解释质量（OmniVinci 4.17→7.40，Qwen2.5-Omni 4.42→6.98）。数据集、MOZAIC-SMALL 精简版、代码与提示词已全部放出。

ToneMamba：用「边界重置」的状态空间模型抓中文声调——在音节/词/韵律短语三级重置双向扫描，口语对话集上比 ToneNet 高 15.9 个点 ⭐

📅 2026-11-25👥 Po-Yu Chiu、Yi-Fen Liu
连续语流中的中文声调识别之所以难，是因为上下文与时长变化会重塑 F0 曲线：同一个三声在词边界和韵律短语边界上的表现可以完全不同，而静态的边界嵌入（boundary embedding）只是把边界位置当作一个附加向量喂进去，并没有真的让模型「在这里断开重算」。ToneMamba 的做法是把边界做成状态空间模型里的重置信号——在音节、词、韵律短语（IPU）三个层级上做双向状态重置，让 SSM 的隐状态在边界处归零重来，从而天然获得层级化的上下文；再用固定权重融合多级表示，并用共享权重的双向扫描 + 通道向方向融合来压缩参数量。声调轮廓本身通过动态音节池化生成，时长信息则通过韵律条件门控（rhythm-conditioned gating）注入。数据上：FCU-VOICE-360 朗读语料 97.9%，MCDC-8 对话语料 74.8%，相对基线 ToneNet 分别提升 0.9 与 15.9 个百分点——差值的悬殊恰好说明了问题所在：朗读语料上静态边界嵌入已经够用，一到自发口语，时长变化成为主导因素，边界重置 + 节奏门控才真正起效。消融显示词级重置最有效，而节奏条件在对话语音上收益最大。（标题原文拼写为 ToneMamaba，正文模型名为 ToneMamba。）

翻译过去的话，韵律还剩下多少？首个词级实证：英-中/泰/越的对应度低于欧洲语对，语序重排越多、局部对应越弱

📅 2026-11-25👥 Haopeng Xie、Ismail Rasim Ulgen、Shengying Zhao、Berrak Sisman、Philipp Koehn
韵律承载强调、情绪与意图，但「同一句话翻译成另一种语言后，重音还落在同一个词上吗」这个问题此前只在欧洲语对上被系统研究过。这篇补上了亚洲语对：以词级为单位，系统分析英语与五种语言（有声调的中文普通话、泰语、越南语，以及作为对照的日语、韩语）之间的音高与能量对应关系。几条结论对做语音翻译、配音与韵律建模的人都很实用：第一，整体对应度显著低于此前报告的欧洲语对估计值；第二，把声调因素做校正后，英-中、英-泰、英-越的音高对应度确实上升——说明词汇声调约束会「占用」一部分音高自由度，压缩了跨语言韵律映射的空间；第三，英-日、英-韩同样低于欧洲语对，可见「有没有声调」并不足以解释全部差异，语系与韵律组织方式本身也在起作用；第四，词序重排的程度与局部对应强度负相关，即使在语义对齐之后依然如此，意味着单纯的语义对齐无法解释跨语言韵律组织的差异。作者据此主张：韵律建模必须显式考虑词汇音高约束与译文的结构上下文，而不能假设「语义对齐了，韵律自然就对齐」。

语音增强的论文很多，但「能落地」的很少，因为真实产品要的不是一个模型，而是一条可配置的处理链加上跨端一致的运行时。GigaEdge Enhance（本期 v4，开源 SDK）正是从这个角度写的：应用可以自行组合神经降噪、响度归一化、动态处理、采样率转换，以及在支持时启用的回声消除；归一化还可以不带神经模型单独运行。发布内容包含一个 8 kHz 的 INT8 降噪模型，以及 48 kHz 的 FP32 判别式与混合式模型；一套共享 C++ 内核通过原生接口支持 ONNX Runtime 与 TensorFlow Lite，并提供 Android、iOS SDK 与 WebAssembly 集成。工程细节上有两点值得抄：一是多个流的上下文可以共享同一份模型资源（独立 stream context 共用权重，避免每路流复制一份）；二是同一条流的连续多帧可以合成一次推理调用（temporal frame grouping），降低调度开销。评测在 EARS-WHAM v2 上进行，与 RNNoise、DPDFNet2 对比质量与处理开销，所有原生与 Web 配置都能快于实时处理，代价是分块（chunk）越大、收集输入所需的时间越长——这正是流式部署里延迟与算力的经典取舍。作者最终交付的是一个可配置的部署系统，以及一份「模型选择 / 分块大小 / 执行环境如何影响可用性」的实验研究。
